1. Executive Summary
Qlyno should not treat search as a simple doctor-directory search. Because the platform connects solo doctors, multi-doctor clinics, hospitals, independent labs, pharmacies and patients, the search layer should act as a Unified Healthcare Discovery Engine.
The core principle is: Search the patient's intent, not just an entity. A patient should be able to type a doctor name, specialty, hospital, clinic, lab test, medicine or healthcare service into one search experience and receive relevant, bookable results.
The architecture must preserve a single doctor identity across multiple practice locations while keeping each organization operationally independent. Likewise, one Qlyno Patient ID should remain persistent across providers, with access controlled by relationship, permission, consent and role.
2. Problem Statement
Some doctors work independently, some work in clinics, some in hospitals, and some do all three.
The same doctor must not appear as multiple unrelated doctors simply because they work at multiple organizations.
Patients may search for a doctor, clinic, hospital, lab test, medicine or service using the same search box.
A patient's search intent changes the ranking logic: 'Dr Sharma' is different from 'cardiologist near me' or 'CBC test'.
Appointments at different organizations must remain operationally separate even when they involve the same doctor.
Search must connect discovery with real availability, location, service, price and organization context.
Patient search and patient-owned health records must be distinguishable so discovery does not expose private medical information.

One Patient ID must not become a universal open medical record.
Organization access must be relationship-, role-, permission- and consent-aware.

Emergency access should follow a separate policy with stronger logging and safeguards.
Discovery results must contain only public/eligible information.

26. Product Decisions to Lock
Doctor identity is independent from practice affiliation.
Hospital and clinic affiliations create distinct operational appointment contexts.
One unified patient search can surface multiple healthcare entity types.
Ranking must be intent-aware and not simply organization-type based.
Availability should be a major ranking signal for actionable provider searches.
AI should interpret natural language but should not invent providers, prices, availability or medical facts.
Search must respect Qlyno's patient privacy and organization boundaries.
A dedicated search index should eventually sit between operational databases and the user-facing search experience.
27. Reference to Existing Qlyno Architecture
This Unified Search design is intended to extend Qlyno's existing patient-centered architecture. The existing Patient Module establishes one persistent Qlyno Patient ID across solo doctors, clinics, hospitals and labs, while preserving privacy and consent boundaries. Existing Doctor, Receptionist, Laboratory, Billing, Hospital Admin, Nurse Station and Super Admin documents establish the organization and role boundaries that this search layer must respect.
The existing Patient Module also describes global search across healthcare records, while the Doctor and Laboratory modules already define operational global search within their respective contexts. The Unified Search layer should sit above these role-specific searches rather than replacing them.
28. Final Product Principle
ONE SEARCH → MANY HEALTHCARE ENTITIES → ONE CONNECTED PATIENT JOURNEY
Qlyno's long-term advantage is not simply helping patients find a doctor. It is helping patients find the right care while maintaining one connected identity across the healthcare ecosystem.
29. V2 Product Decision — Intent-First Search Hierarchy
Critical correction to the original unified-search modelA flat result list containing Doctor, Clinic and Hospital as equal entities creates a conversion conflict. If a patient searches for a specific doctor, making the clinic or hospital the primary result can hide the doctor and shift the patient's decision toward the organization. Qlyno should therefore use an intent-first hierarchy: the entity matching the patient's intent is primary; related organizations, doctors, locations and services are supporting context.

The doctor remains the primary searchable professional identity.
A hospital or clinic cannot accidentally become the only visible brand when the patient searched for a doctor.
The same doctor can receive bookings from multiple affiliated organizations.
The doctor does not need separate public profiles for each hospital/clinic.
Each organization still receives appointments that belong to its own operational context.
Qlyno can measure doctor-level discovery and conversion separately from organization-level conversion.

44. Search Personalization Without Cannibalization
Patient context can improve ranking, but personalization must not silently replace the user's explicit search intent.
If patient searches a specific doctor, show that doctor first even if another provider is closer.
If patient searches a specialty, use location and availability to rank doctors.
If patient searches a hospital by name, show the hospital first.
Connected providers may receive a small relevance boost when appropriate, but should not override exact-name matches.
Sponsored results, if introduced, must be clearly labelled and must not bypass verification or safety rules.

47. Updated Product Principle
ONE SEARCH → CORRECT PRIMARY INTENT → CONNECTED HEALTHCARE CONTEXT
Qlyno should not force the patient to choose between a doctor, clinic or hospital before understanding what the patient searched for. Instead, the search engine should identify the patient's intent and make the matching entity primary. For provider-intent searches, the doctor remains primary and the hospital/clinic becomes the practice context. For organization-intent searches, the hospital or clinic becomes primary and its doctors become supporting discovery options.
48. V2 Acceptance Criteria
Searching a specific doctor returns one primary doctor identity, not duplicate hospital/clinic doctor cards.
A doctor profile can display multiple active practice affiliations.
Each affiliation can have its own location, fee, schedule, service and availability.
Doctor-intent searches keep the doctor visually and functionally primary.
Hospital/Clinic/Solo are available as practice-context filters for doctor-intent searches.
Hospital-intent searches make the hospital primary and expose departments/doctors underneath.
Clinic-intent searches make the clinic primary and expose doctors/services underneath.
The same doctor can be linked to a hospital and clinic without creating duplicate doctor identities.
Hospital and clinic appointments remain operationally isolated through affiliation and organization context.
Doctor-level and organization-level discovery/booking analytics are separately measurable.
Ranking changes according to query intent rather than using a universal entity-type ranking.
AI can interpret natural-language intent but cannot invent availability, price, provider identity or medical diagnosis.
Search results only expose verified/public information appropriate for discovery.
The architecture prevents organization branding from unintentionally hiding the doctor in doctor-intent searches.
